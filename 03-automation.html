③ 自动化评测与回归 L2 执行引擎层

对应职责「建设自动化评测能力，支持模型、prompt、Agent 策略和产品版本对比」：以评测平台为载体，把「跑评测」变成像 CI 一样的基础设施——一键触发、自动执行、结果可比。

评测平台技术架构

接入层Entry
Web 控制台（发起任务/看报告） OpenAPI / SDK（Python） CI 集成（Jenkins/GitLab 触发器）
调度层Orchestrator
评测任务编排（DAG） 并发 / 限流 / 重试 缓存（同输入命中跳过） 多模型路由（LiteLLM）
执行层Runner
被测对象适配器（模型/API/Agent/产品端） Agent 沙箱执行器（工具/浏览器/代码） 轨迹采集器（步骤/工具调用/耗时）
评测器层Evaluators
规则评测器（格式/关键词/正则/SQL 断言） 传统指标（BLEU/ROUGE/精确匹配） LLM-as-Judge（打分/成对比较/事实核查） 多模态评测器（VLM Judge）
存储分析层Storage
评测结果库（PostgreSQL） 明细样本存储（对象存储） 追踪分析（Langfuse） 看板数据服务

评测器选型矩阵（什么指标用什么评）

评测器类型适用指标优点局限与对策
规则 / 代码 格式合规、JSON 可解析、工具参数合法、敏感词命中、延迟成本 零成本、100% 可靠、可复现 只能覆盖结构性质量 → 作为所有任务的前置闸门
传统指标 有标准答案的场景：精确匹配、ROUGE、检索命中率 客观、快 对开放式生成区分度低 → 限定在有参考答案的数据集
LLM-as-Judge 正确性、相关性、幻觉判定、风格、成对偏好 可规模化覆盖主观维度 存在偏置（位置/长度/自我偏好）→ 见下方校准机制
人工标注 高价值 / 高争议 / Judge 不确定样本 金标准 贵且慢 → 只做抽样校准与仲裁（见节点④）

三层回归防线（Regression Strategy）

⚡防线一：Commit 级（冒烟）

触发：Prompt / 策略代码提交。跑小规模哨兵集（约 300 条），5~10 分钟出结果，P0 指标跌破基线立即阻断合并。追求「快」。

📦防线二：版本级（全量）

触发：候选版本构建 / 发版前。跑全部评测集 + bad case 回归集，生成完整评测报告与版本对比，作为上线门槛输入。追求「全」。

🛰️防线三：线上巡检

触发：定时（小时级）。对线上环境跑金标巡检集，监控效果与延迟漂移，异常自动告警并可触发熔断。追求「稳」。

# 评测任务配置示例（平台 YAML）
task: release-gate-app-2.5.0
trigger: pre_release          # commit | pre_release | cron | manual
candidates:
  - type: model,    ref: "gpt-x-2026-08"
  - type: model,    ref: "internal-llm-v9"      # 对比模型
  - type: prompt,   ref: "agent_planner@v14..v16" # 对比 prompt 版本
  - type: agent_strategy, ref: "react | plan_execute" # 对比 Agent 策略
datasets: [core_qa_v12, agent_task_v8, regression_badcase_all]
evaluators: [rule_gate, llm_judge_v3, trajectory_check]
repeat: 3                    # 同输入多次采样，测稳定性
report: { compare_baseline: app-2.4.1, publish: dashboard }

四维版本对比能力

同一份评测结果库，支持按四个维度任意切片对比，输出「谁更好、好在哪、哪些 case 翻转」：

对比维度典型问题输出物
模型对比新模型 vs 线上模型，值不值得换？成本增加多少？指标对比表 + 翻转 case 清单 + 成本差
Prompt 对比Prompt v16 是否解决了角色漂移？有没有引入新问题？逐指标增减 + 回归集通过率变化
Agent 策略对比ReAct vs Plan-and-Execute 哪个任务完成率更高？步数效率呢？成功率 / 平均步数 / 工具调用对比
产品版本对比App 2.5.0 相比 2.4.1 端到端质量是升是降？基线对比报告 + 门槛校验结果

LLM-as-Judge 校准机制（保证自动评测可信）

  • 金标集校准：维护人工标注的金标集，Judge 上线前与其对齐，一致率 ≥ 90% 才可投产；每月复检防漂移。
  • 去偏设计：成对比较随机交换位置消除位置偏置；长度归一化提示消除长度偏好；答案匿名化消除模型自我偏好。
  • 不确定兜底：Judge 输出置信度，低置信样本自动转人工标注队列，避免「错得安静」。
  • 证据链要求：Judge 必须输出 evidence_span（判定依据原文），便于人工抽检时快速复核。
