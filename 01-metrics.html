① 评测指标体系 L0 标准指标层

对应职责「建立 LLM / Agent / 多模态应用的评测指标」：为所有被测对象建立统一、可量化、分优先级的指标树，核心原则是把产品体验问题抽象成可测指标，而不是只做主观评价。

🎯 设计原则：每个指标必须有明确定义、计算公式、数据来源、评测方式和目标值。无法度量的指标不进入体系；只有主观判断的场景必须先通过标注校准转化为可测项。

核心指标定义卡（示例）

每个指标在指标字典中以「定义卡」形式登记，保证跨团队口径一致：

方法论：如何把「体验问题」抽象成可测指标

  1. 收集主观抱怨从用户反馈、客服工单、产品评审中收集原始体验描述，如「回复太啰嗦」「答非所问」。
  2. 聚类归并将抱怨聚类为可命名的质量维度（冗余度、相关性、结构清晰度等）。
  3. 给出可操作定义每个维度写出「什么算好、什么算差」的行为化描述与典型正反例。
  4. 设计量表转化为 1-5 分李克特量表或二元判定，并配套锚定样例（anchor examples）。
  5. 校准验证多人标注 → 计算一致性（Kappa）→ 修订规范 → 达标后进入指标字典，可交由 Judge 自动化执行。
# 指标字典登记示例（YAML）
metric: hallucination_rate
name: 幻觉率
formula: hallucinated / total_answers
evaluator: llm_judge_v3    # 自动评测器
human_audit_ratio: 0.05    # 5% 人工抽检
dimension: quality
priority: P0
target: "<=0.02"
owner: eval-team
datasets: [core_qa_v12, rag_faq_v5]
