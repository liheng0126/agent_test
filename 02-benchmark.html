② Benchmark 与 Bad Case 库 L1 数据资产层

对应职责「设计并维护覆盖核心用户场景的 benchmark 和 bad case 库」：评测集是整个体系的「考卷」，其质量直接决定评测结论的可信度。核心思路：分层构建 + 线上回流 + 持续保鲜。

🎯 建设原则：评测集分布必须贴近真实流量分布。一份离真实场景越来越远的评测集，分数再高也没有业务意义。通用学术 benchmark 只做参考基线，业务 benchmark 才是决策依据。

分层 Benchmark 体系

🌍L1 通用基线集

引用学界公开 benchmark（MMLU、GSM8K、HumanEval 等）+ 内部通用能力集，用于模型选型与横向对比，约占 20%。

🎯L2 核心场景集

覆盖 Top 核心用户场景（按流量 / 价值排序），每场景独立成集、独立看分，是上线决策的主要依据，约占 50%。

🧨L3 对抗与边界集

越狱、注入、超长上下文、多轮诱导、语义陷阱、不可答问题（拒答测试）等边界能力，约占 15%。

♻️L4 回归 Bad Case 集

线上真实问题回流沉淀，每条都「来路可查」，保证已修复问题不复发，约占 15% 且持续增长。

评测集数据来源（四条生产线）

A
真实日志脱敏线上采样 → 清洗 → 分层抽样
B
人工构造按场景 spec 编写 → 交叉评审
C
模型合成种子扩增 → LLM 生成 → 人工过滤
D
问题回流Bad Case / 用户反馈 → 复现入库
  • 真实日志线：按「场景 × 难度 × 用户类型」分层抽样，脱敏处理（去 PII），保留原始上下文，最贴近真实分布。
  • 人工构造线：依据产品场景规格（spec）编写，覆盖设计中的长尾分支；双人评审保证题面无歧义。
  • 模型合成线：用强模型对种子样本做改写 / 扩增（同义改写、难度升维、干扰注入），必须经人工质检过滤后才能入库。
  • 问题回流线：来自 bad case 库与线上告警，是回归防线的弹药来源（详见下方）。

Bad Case 库：收集 → 分类 → 复现 → 入库 → 回归

  1. 收集五个来源：自动化评测失败样本、人工标注问题、用户负反馈（点踩/投诉）、客服工单、竞品对比落差。
  2. 去重与归并按问题指纹（场景 + 问题类型 + 触发模式）归并，避免同一 pattern 的重复 case 稀释回归权重。
  3. 复现与最小化确认在当前版本可复现，剥离无关信息形成最小复现单元（最小 prompt + 最小上下文）。
  4. 分类打标标注问题类型（幻觉 / 上下文遗忘 / 角色漂移 / 工具调用失败 / 安全风险 / 格式错误…）、严重等级、影响场景。
  5. 入库登记写入 bad case 库，关联：来源单号、版本号、复现脚本、期望行为、修复 Owner。
  6. 回归闭环自动汇入 L4 回归集，在每个候选版本上重跑；修复确认后转入「哨兵观察」状态持续监控。
